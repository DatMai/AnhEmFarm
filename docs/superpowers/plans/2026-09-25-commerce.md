# AnhEmFarm Commerce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current storefront into a persistent customer and administrator commerce application with verified accounts, SKU inventory, COD checkout, fulfillment, and reproducible deployment.

**Architecture:** Retain the React/Vite frontend and introduce a NestJS modular monolith with PostgreSQL and Prisma. Serve the frontend, server-rendered public product pages, and REST API on one origin; run email delivery in a separate process using the same application and PostgreSQL outbox. Keep business invariants in services and database constraints.

**Tech Stack:** Node.js 24.21.0, TypeScript, NestJS 11.2.6 (Express), PostgreSQL 17, Prisma 7.10.0 with its PostgreSQL adapter, React, Vite, React Router, TanStack Query, Vitest, Playwright, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-25-commerce-design.md` (read this with the plan).

## Global Constraints

- The core stack is React, Node.js + TypeScript, and PostgreSQL. Django is excluded.
- English for every repository document and all text inside the app; Vietnamese localization will follow in a later phase.
- Version 1 serves one store, one warehouse, VND amounts, and domestic delivery.
- Online payment, carrier synchronization, multiple sellers, coupons, and loyalty points are outside this release.
- REST API under `/api/v1`.
- Passwords are 12–128 characters and hashed with Argon2id through a maintained library.
- Email-verification tokens expire after 24 hours; password-reset tokens after one hour.
- Customer session TTL is seven days; admin TTL is 12 hours.
- Quantities are integers from 1 to 99 per SKU, with at most 50 cart lines.
- Store a quote in PostgreSQL for 15 minutes, tied to the user, lines, address, and delivery fee.
- Only ADMIN may upload. Limit images to 5 MB, validate actual JPEG/PNG/WebP content and pixel count, re-encode to remove metadata, and generate random object names.
- Back up PostgreSQL daily and before migrations, store backups off the application host for at least 30 days, and version/back up images correspondingly.
- SQLite cannot substitute for PostgreSQL in stock-concurrency tests.
- No actual prices, contact details, approved policies, or inventory have been supplied. Development fixtures cannot enable live sales.

## Review Focus

1. A checkout response is lost after commit: retrying the same key or submitting a new key for the same quote must return one order and deduct stock once (Task 11).
2. A second browser tab changes the cart during checkout: preserve the changed cart and show an explicit review message (Tasks 10, 14).
3. An account is suspended while requests are in flight: a mutation that acquires its account lock after suspension must fail, and old cookies must remain invalid after reactivation (Tasks 4, 13).
4. A JPEG has a tiny compressed size but enormous decoded dimensions: reject before decoding the full image or publishing an object (Task 7).
5. A server restarts after taking an email job, or after restoring an old database: reclaim expired worker leases without duplicating orders, and reject sessions from before restoration (Tasks 5, 17).

## API and persistence contracts

All routes below are relative to `/api/v1`. JSON bodies reject unknown fields. Return `{code, message, fields?, requestId}` on errors. Pagination is `{items, page, pageSize, total}`, page starts at 1, pageSize defaults to 20 and is at most 100; no arbitrary SQL sort names. IDs are UUIDs. Dates serialize as UTC ISO strings. Amounts are integer VND JSON numbers with a safe upper bound; cap a SKU at 1,000,000,000 VND and guard every calculated total with `Number.isSafeInteger`.

| --- | --- |
| Identity | `GET /auth/csrf`, `POST /auth/register`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `POST /auth/verify-email`, `POST /auth/resend-verification`, `POST /auth/forgot-password`, `POST /auth/reset-password`, `POST /auth/change-password` |
| Account | `PATCH /account`, `GET/POST /account/addresses`, `PATCH/DELETE /account/addresses/:id` |
| Public catalog/content | `GET /categories`, `GET /products`, `GET /products/:slug`, `GET /shipping-zones`, `GET /content/:slug`, `GET /store` |
| Cart | `GET /cart`, `PUT /cart/items/:variantId`, `DELETE /cart/items/:variantId`, `POST /cart/merge` |
| Purchase | `POST /quotes`, `POST /orders`, `GET /orders`, `GET /orders/:id`, `POST /orders/:id/cancel` |
| Catalog admin | `GET/POST /admin/categories`, `PATCH /admin/categories/:id`, `GET/POST /admin/products`, `GET/PATCH /admin/products/:id`, `POST /admin/products/:id/variants`, `PATCH /admin/variants/:id`, `POST /admin/media`, `POST /admin/inventory/:variantId/adjustments` |

Collection routes enforce bounded pagination. Item queries scope customer access by both ID and owner ID; unauthorized foreign IDs return 404. Auth failures return 401, forbidden roles/CSRF 403, invalid input 422, unavailable/changed stock or version conflict 409, too many requests 429, temporary infrastructure failure 503.

Use Prisma models with singular PascalCase names and `@@map` snake_case plural SQL names. Columns stay quoted camelCase. Every mutable aggregate has `version Int @default(1)`, timestamps, and UUID keys. Variant also has `commercialVersion Int @default(1)`: price, pack, label, and sale-setting edits increment both versions; stock changes increment only version. Product version covers publication/confirmation/restriction changes. Use `BigInt` for stored totals, convert only after the safe-integer check in response serializers.
